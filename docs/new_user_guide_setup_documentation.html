Setup & User Guide

This guide is for anyone who's received a copy of this project's folder and wants to get it running on their own computer — no prior experience assumed. Every step is explained in plain language, starting from the moment the folder is downloaded.

What you'll end up with: a working copy of the chat app running on your own computer, connected to your own database, using your own AI keys — completely independent from the original.

What's Inside This Folder

The folder you've received contains the app's code, but not its secrets — those have been removed for safety. Here's what to expect:

File / FolderWhat it is
app.pyThe main application code
templates/, static/The chat screen's look and feel
requirements.txtA list of everything the app needs installed
.env.exampleA list of the secret values you'll need to fill in yourself
chat_message.sql, request_log.sql, user.sql (or a single local_backup.dump)A copy of the database's structure — and, if included, some sample data — ready to load in. Not every copy of this project includes these; if yours doesn't, that's fine too, see the restore section below
power-bi/*.pbixThe analytics dashboard file(s)
No real passwords or API keys are included in this folder. You'll create your own in the steps below — this is intentional and for your safety. Message content in any included sample data is encrypted, and any included passwords are one-way hashed — neither is readable without secrets you don't have, which is exactly why they're safe to include as sample data.

Setting Up the Folder

Saving the Folder to Your Computer

  1. If the folder arrived as a .zip file, right-click it and choose Extract All (Windows) to unzip it
  2. Move the extracted folder somewhere easy to find — for example, directly into your Documents folder, or a dedicated folder like C:\Projects\
  3. Avoid saving it inside a cloud-synced folder (like a OneDrive or Dropbox folder) if possible — these can sometimes interfere with Python's virtual environment step later
  4. Rename the folder if you like — nothing inside depends on the exact folder name
A sensible final location might look like: C:\Users\YourName\Documents\flask-chatgpt-app\

Opening It in VS Code

  1. Open VS Code
  2. File → Open Folder
  3. Select the folder from the step above
  4. Open a terminal inside VS Code: Terminal → New Terminal

Everything from here on happens inside this terminal.

Installing the App

Create a Virtual Environment

This keeps the project's Python packages separate from anything else on your computer:

python -m venv venv

Then turn it on. On Windows (Git Bash):

source venv/Scripts/activate

You'll know it worked when (venv) appears at the start of the terminal line — do this every time you come back to work on the project.

Install the Required Packages

With (venv) active, install everything listed in requirements.txt in one go:

pip install -r requirements.txt

This reads the file already included in the folder and installs the exact same packages the original project used — no need to know what each one does individually.

Setting Up the Database

Install PostgreSQL & pgAdmin

  1. Download PostgreSQL from postgresql.org
  2. Run the installer, keeping all default options
  3. When asked, set a password for the postgres user — write this down, you'll need it shortly
  4. Keep the default port, 5432
  5. pgAdmin installs automatically alongside PostgreSQL — this is the visual tool used in the next steps

Create an Empty Database

  1. Open pgAdmin
  2. Enter the password from the previous step when asked
  3. In the left sidebar, expand Servers → PostgreSQL
  4. Right-click Databases → Create → Database
  5. Name it flask-chat-app and click Save

At this point the database exists, but it's completely empty — the next step fills it with the included structure and sample data.

Restore the Included Data

How to load in existing data depends on what's actually included in the folder you received — check first, then follow the matching method below.

Option A: A local_backup.dump file is included

This is the simplest method — one command restores everything (structure and data) in one go. In your terminal:

pg_restore --no-owner --no-privileges -d "postgresql://postgres:YOUR_PASSWORD@localhost:5432/flask-chat-app" local_backup.dump

Replace YOUR_PASSWORD with the PostgreSQL password you set during installation. If Git Bash says pg_restore: command not found, use the full path instead, adjusting the version number to match what you installed:

"C:\Program Files\PostgreSQL\18\bin\pg_restore" --no-owner --no-privileges -d "postgresql://postgres:YOUR_PASSWORD@localhost:5432/flask-chat-app" local_backup.dump

Option B: Individual .sql files are included instead

Load each one in using pgAdmin's Query Tool:

  1. Right-click your new flask-chat-app database → Query Tool
  2. Open each included .sql file (e.g. user.sql) in a text editor, copy its contents, paste into the Query Tool, and click ▶ Run
  3. Repeat for each .sql file included in the folder
Don't worry about getting the order exactly right — if one file mentions a table another file hasn't created yet, just run that one again after the others finish; pgAdmin will tell you clearly if something's missing.

Option C: No data files are included at all

That's fine too — nothing extra to do here. The very first time you run the app (python app.py), it automatically creates every table it needs, just empty. The Power BI dashboard will simply show zeros until you've signed up and sent a few chat messages yourself — that's expected, not a problem.

Whichever method applies, once it's done, the app's tables (and any included sample data) exist in your own local database, completely independent of the original.

Creating your own backup later (optional)

Once you've been using your own copy for a while, you might want to save a backup of your own data — for example, before trying something risky, or to move it to another computer. The same tool used to create the included backup can make one of your own:

pg_dump -h localhost -U postgres -d flask-chat-app -F c -f my_backup.dump

If Git Bash says pg_dump: command not found, use the full path instead, adjusting the version number to match what you installed:

"C:\Program Files\PostgreSQL\18\bin\pg_dump" -h localhost -U postgres -d flask-chat-app -F c -f my_backup.dump

This creates my_backup.dump in your current folder — a single file holding everything, which can be restored later using the same pg_restore command from Option A above.

Your Own Secrets

Getting Your Own API Keys

The app relies on a few outside services. Since none of the original credentials were included, you'll need your own free accounts for these:

ServiceWhere to get a keyCost
OpenAIplatform.openai.com/api-keysRequires adding a small amount of billing
Google Geminiaistudio.google.com/apikeyFree tier available, no card needed
Google Sign-In (OAuth)console.cloud.google.com → APIs & Services → CredentialsFree
The app works fine with just one AI key. If you only set up Gemini (the free one), the chat will simply use that every time — the OpenAI-then-Gemini fallback only matters if you add both.

Creating Your .env File

The folder includes a file called .env.example — a template showing exactly which values are needed, without any real secrets in it.

  1. Make a copy of .env.example in the same folder
  2. Rename the copy to exactly .env
  3. Open it and replace each placeholder with your own real values
OPENAI_API_KEY=your_real_openai_key
GEMINI_API_KEY=your_real_gemini_key
APP_SECRET_KEY=make_up_any_random_text_here
ENCRYPTION_KEY=see_below
FLASK_SECRET_KEY=make_up_any_random_text_here
GOOGLE_CLIENT_ID=your_real_google_client_id
GOOGLE_CLIENT_SECRET=your_real_google_client_secret
DB_PASSWORD=the_postgres_password_you_set_earlier

For ENCRYPTION_KEY, generate a fresh one with this command, and paste the result in:

python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
Never share your .env file with anyone, or upload it anywhere. It holds all your real secrets. It's already set up to be ignored by Git automatically.

Running the App

Starting the App

With (venv) active and .env filled in, start the app:

python app.py

Look for a line like Running on http://127.0.0.1:5000 — then open that address in a web browser.

If it shows an error instead — it's almost always a missing or mistyped value in .env. The error message names exactly which one is missing, e.g. OPENAI_API_KEY is not set.

Creating Your First Account

The app will show a sign-in page first. Since this is a fresh database, no accounts exist yet:

  1. Click "Don't have an account? Sign up"
  2. Enter any email and a password (at least 8 characters)
  3. Click Sign Up — you'll be taken straight into the chat screen

From here, the app works exactly like the original — chatting, conversation history, and the sidebar all function the same way, just using your own local setup.

Analytics Dashboard

Install Power BI Desktop

Power BI Desktop is free, Windows-only, and can be installed from the Microsoft Store or Power BI's website.

Opening & Reconnecting the Dashboard

The included .pbix file was built against the original database — it needs to be pointed at your local database before it will show any data.

  1. Open the .pbix file from the power-bi folder
  2. Go to Home → Transform data
  3. In the left sidebar, click on a table (e.g. public request_log)
  4. Find the formula bar at the top, showing something like:
    = PostgreSQL.Database("some-old-address", "flask-chat-app")
  5. Replace it with your own local connection:
    = PostgreSQL.Database("localhost:5432", "flask-chat-app")
  6. When prompted, log in using postgres and the password you set during installation
  7. Repeat for every other table in the sidebar
  8. Click Close & Apply
Once reconnected, the dashboard will show whatever data exists in your own local database — since it started from the included sample data, it should show something right away, and will keep updating as you use the chat app yourself.

Going Live (Optional)

Everything above gets the app running on your own computer. If you'd also like your own copy to be a real, public website — not just running locally — here's how, using the same free services the original was built with: Neon (cloud database) and Render (hosting).

This whole section is optional. If you just want to use the app on your own computer, you're already done — nothing below is required.

Your Own Cloud Database

  1. Sign up free at neon.tech
  2. Create a new project — Neon gives you a connection string, e.g. postgresql://user:pass@host/dbname?sslmode=require
  3. Copy your local data across (optional, only if you want your live site to start with the same sample data):
# Export from your local database
pg_dump -h localhost -U postgres -d flask-chat-app -F c -f my_backup.dump

# Import into your new Neon database
pg_restore --no-owner --no-privileges -d "your-neon-connection-string" my_backup.dump

Deploying Your Own Copy

One line of code needs your own details

Find this in app.py:

@app.route('/login/google')
def login_google():
    if os.environ.get("RENDER"):
        redirect_uri = 'https://flask-chatgpt-app.onrender.com/login/google/callback'
    else:
        redirect_uri = 'http://127.0.0.1:5000/login/google/callback'
    return google.authorize_redirect(redirect_uri)

Change the web address inside the quotes to whatever your own live address will be, once you know it (you'll get this after your first deploy below) — for example:

        redirect_uri = 'https://your-own-app-name.onrender.com/login/google/callback'
This only matters if you plan to use Google Sign-In on your live site. If you're only using email/password login, you can skip this step entirely.

Deploy to Render

  1. Push your copy of the code to your own GitHub repository (see the earlier steps in this guide if you haven't already)
  2. Sign up at render.com
  3. New + → Web Service → connect your GitHub repository
  4. Build Command: pip install -r requirements.txt
  5. Start Command: gunicorn app:app
  6. Health Check Path: /login-page — important, see the warning below
  7. Add every value from your own .env as an Environment Variable in Render's dashboard, plus your Neon connection string under the key NEON_DATABASE_URL
  8. Click Create Web Service
Don't skip the Health Check Path. Render checks whether your app is alive by requesting its home page (/). Since this app's home page requires being logged in, the default health check will always fail and Render will keep shutting the app down. Setting it to /login-page instead — a page that doesn't require login — fixes this.

If using Google Sign-In, update Google Cloud Console too

Once you know your live address (Render shows it after your first deploy, something like https://your-app-name.onrender.com), add it as a second Authorized redirect URI in your Google Cloud Console project — alongside your existing localhost one, not replacing it:

https://your-app-name.onrender.com/login/google/callback

Then go back and update the line in app.py with this real address, save, commit, and push — Render will automatically redeploy with the fix.

Optional: CI/CD & ETL

This project includes a small CI/CD pipeline (automated tests run on every push, via GitHub Actions) and a scheduled ETL job (daily usage summaries) — both already set up in .github/workflows/.

The ETL job needs its own NEON_DATABASE_URL secret added under your GitHub repo's Settings → Secrets and variables → Actions to work. Without it, that one workflow will simply show as failing in your Actions tab — that's harmless and just means it hasn't been configured yet, not that anything is broken.

Both of these are entirely optional — the chat app itself works completely fine without either one.

Using the App

This section is for day-to-day use, once everything above is set up.

Creating an Account

  1. Open the app's address in a browser
  2. Choose one of two ways to sign in:
    • Email & password — click "Don't have an account? Sign up"
    • Google account — click "Sign in with Google" (only works if you set up your own Google credentials earlier)

Using the Chat

  1. Type a message in the box at the bottom and press Send (or hit Enter)
  2. The AI's reply appears above the input box a moment later
  3. Keep chatting by typing another message — the AI remembers the conversation so far
As with any AI, replies can occasionally be wrong. Always double-check anything important, and avoid sharing sensitive, personal, or confidential information.

Managing Conversations

  • Starting a new topic? Click + New Chat in the sidebar
  • Returning to an old conversation? Click it in the sidebar list
  • On a phone? Tap the menu icon (☰) to open the sidebar
  • Signing out? Click Log out at the bottom of the sidebar

Optional: Going Live

Everything above gets the app running on your own computer. This section is only needed if you want to take it further — putting your own copy on the internet, so anyone with a link can try it, the same way the original was deployed.

Your Own Cloud Database

Your local database only exists on your own computer — nothing outside it can reach it. To go live, you need a database that lives on the internet instead. This project was built using Neon, a free, serverless PostgreSQL host.

  1. Sign up free at neon.tech
  2. Create a new project — Neon gives you a connection string that looks like:
    postgresql://user:password@ep-something.aws.neon.tech/dbname?sslmode=require
  3. Copy that connection string — add it to your .env file as NEON_DATABASE_URL

Moving your data across (optional)

If you want your live site to start with the same data you've been testing with locally, export it and import it into Neon:

# Export from your local database
pg_dump -h localhost -U postgres -d flask-chat-app -F c -f my_backup.dump

# Import into Neon
pg_restore --no-owner --no-privileges -d "your-neon-connection-string" my_backup.dump

If you'd rather your live site start completely empty, skip this — it'll simply build its tables fresh the first time it runs.

Deploying Your Own Copy

Render is a free hosting service that runs the app continuously online, and automatically redeploys it whenever you push new code to your GitHub repository.

  1. Sign up at render.com
  2. New + → Web Service → connect your GitHub repository
  3. Build Command: pip install -r requirements.txt
  4. Start Command: gunicorn app:app
  5. Health Check Path: set this to /login-page — not the default /, since / requires being logged in and Render's automatic health check needs a page that always responds normally
  6. Add every value from your .env file as an Environment Variable in Render's dashboard (the real values, no quote marks around them)
  7. Click Create Web Service
Free tier note: the live app "falls asleep" after about 15 minutes without visitors, and takes up to a minute to wake back up on the next visit. This is a standard tradeoff of free hosting, not a bug.

One code change you'll need to make first

This copy still has the original project's live web address written into one line of app.py, used specifically for Google sign-in:

redirect_uri = 'https://flask-chatgpt-app.onrender.com/login/google/callback'

Once Render gives you your own live address (something like https://your-app-name.onrender.com), update this line to use it instead. This only matters for the live version — your local copy running on your own computer is unaffected either way.

Don't forget: Google Sign-In needs your live address too

In Google Cloud Console, under your OAuth Client's Authorized redirect URIs, add your own live address alongside the existing localhost one:

https://your-app-name.onrender.com/login/google/callback

About the included automation (optional)

This copy also includes an automated testing setup (GitHub Actions) and a scheduled daily data-summary job. The testing part works immediately with no setup. The daily job needs your own Neon connection string saved as a GitHub secret named NEON_DATABASE_URL (repo → Settings → Secrets and variables → Actions) if you want it to run — otherwise it's safe to simply ignore, or turn off entirely by deleting .github/workflows/etl.yml.
